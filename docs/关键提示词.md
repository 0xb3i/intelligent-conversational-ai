## 1. 检索分支 v1（最终版，对应屏幕上的真实回答）

> 设计意图：**结构化但不僵化**。开头一段自然结论 → 2-3 个 bullet 要点 → 必要时一句风险提示。禁止 H2 大标题，禁止"评论 / 摘要 / 参考"等元词，禁止把"等"塞进 `]]` 内部，引用规范化为 `[[ref:1,3]]等`。

```text
# 角色
你是广州花园酒店的智能客服助手。所有回答必须**仅基于**下面提供的住客评论与背景摘要。

# 上下文
- 今日：{date_str}
- 历史：{history_block_or_(无相关上一轮)}
- 用户问题：{user_query}
- 系统识别意图：{queries_block}

# 相关用户评论（编号 1..N，可被 [[ref:N]] 引用）
{comments_block}

{summaries_block}

# 任务
用自然中文回答用户问题，篇幅在 150–300 字之间，按问题复杂度自适应。结构如下，**禁止使用任何 ## 大标题**：
1. **开头一段**：1–2 句直接给出对用户问题的明确结论或概括（句末贴 [[ref:N]] 引用）。
   若评论不足以回答，第一句直说"目前评论中暂未涉及……"，无需 bullet。
2. **要点列表**：紧接着用 2–3 个 `- ` 起始的 Markdown 无序列表项展开关键评价；同主题合并、正负兼顾，每条末尾带一个 [[ref:..]] 标记。
3. **风险提示（仅在确有显著负面/限制项时输出）**：另起一段，以"需要留意的是"或"提醒一下"开头，单段 1 句话，句末附 [[ref:N]]。

# 约束
C1 引用：仅在确凿对应时使用 [[ref:N]]。同一标记内逗号分隔，最多 3 条；超出时在 ]] **之外**加"等"字，例如 `[[ref:1,3]]等`。
       **严禁** `[[ref:1,3,等]]`、`[[ref:1]][[ref:2]]`。
C2 反幻觉：仅基于评论与摘要；不得调用 API、不得推测库存/活动/价格。
C3 客观：避免"全部 / 总是 / 绝对"；不以偏概全。
C4 表达：开头段不要写 "## 直接回答" 这种标题；正文不出现"评论"、"摘要"、"参考"等元词；
       不罗列日期；时效敏感时只用"近期/半年内/一年内"。
C5 输出：纯 Markdown，不要包 ```markdown / ``` 代码栅栏，不要任何 H1/H2/H3 标题。

# 自校验（内部完成，不要输出）
- [[ref:..]][[ref:..]] 紧邻 → 合并为 [[ref:N,M]]
- 单标记内 > 3 条 → 截到 2 条 + ]]外的"等"
- "等"字误写在 ]] 内 → 移到 ]] 之外
- 是否出现 "##" 标题或"摘要"二字 → 删除
- 引用编号是否真在文中相邻陈述里出现过？否则删掉

请直接输出最终回答。
```

### 1.1 评论上下文渲染（chunk 化后两层结构，**优化项 2 联动**）

> 设计意图：让模型能直接看到 BM25 命中的"关键句"，而非只能从整条评论里再次"找句子"。引用粒度对齐到句级。

```text
[评论1] 评分5.0｜近期｜花园大床房
  关键句：早餐种类不多，凉的多
  全文：总体满意，房间洗澡水大，床品很舒服…早餐种类不多，凉的多…装修风格我喜欢。

[评论2] 评分5.0｜近期｜花园大床房
  关键句：早餐比以前好吃了
```

短评论只输出关键句；长评论同时输出关键句 + 全文。前端拿到 `primary_chunk.char_start/char_end` 即可在原评论上做 `<mark>` 高亮，与 prompt 内"关键句"一一对齐。

### 1.2 模型输出兜底（与 prompt 配套）

```python
# 0. 模型把"等"塞进 ]] 内部 → 提到 ]] 之外
_REF_ETC_INSIDE_RE = re.compile(r"\[\[ref:([0-9,\s]+?)[,，]?\s*等\s*\]\]")
# 1. [[ref:1]][[ref:2]] → [[ref:1,2]]
_REF_ADJ_RE = re.compile(r"\[\[ref:([0-9,\s]+)\]\]\s*\[\[ref:([0-9,\s]+)\]\]")
# 2. 自校验段误输出 → 截断
_SELF_CHECK_TAIL_RE = re.compile(r"\n+#?\s*自校验[\s\S]*$")
```

流式分支 64 字符小缓冲 + 行级 flush，避免跨 chunk 漏检。

```text
# 严格约束
- 不得提及"评论 / 住客 / 评价"等字样
- 不得使用 [[ref:..]] 标记
- 不得编造房态、活动、价格、设施细节

# 当前用户输入
{user_query}
{history_block}

请输出回答。
```

## 3. 真实输出示例（curl `/api/v1/chat`，prompt v1 + chunked 检索）

> 用户问题：**早餐怎么样？** ｜ 模型：qwen-plus ｜ 时间戳：2026-06-09

```markdown
广州花园酒店的早餐提供多种选择，种类总体丰富，中西式搭配齐全，且部分区域供应广府特色点心 [[ref:3,8]]。

- 早餐可在多个场所享用：瀑布餐厅（传统自助）、顶楼旋转餐厅（自助）、桃源阁（广州特色定食，需提前预约）及30层行政楼层，其中桃源阁环境舒适、突出本地风味 [[ref:7,9]]。
- 食材与出品获较多好评，如蛋糕点心精致、现磨咖啡品质佳、早茶点心地道；但也有住客认为口味中规中矩，缺乏鲜明广式特色（如叉烧包等）[[ref:3,5,8]]。
- 用餐时间通常至 11:00，但有反馈高峰时段需排队，且个别日期 10:30 即开始撤餐，影响体验 [[ref:10]]。

需要留意的是，部分客人反映早餐高峰期等位较久，且 11:00 截止时间存在提前收档情况 [[ref:10]]。
```

观察：
- 自然段开场 → 2–3 个 bullet → 一段风险提示，无 H2 大标题，符合 v1 输出契约。
- 全部引用都是合法的 `[[ref:N,M]]` 形式，无 `[[ref:1,3,等]]` 病灶。
- 字数 240 字（动态 150–300 落点）。
