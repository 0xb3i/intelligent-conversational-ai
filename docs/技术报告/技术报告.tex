\section{评论文本分块与引用高亮}

\subsection{痛点}

原系统从入库、建索引到检索、拼接，全程把「整条评论」当成最小检索单元。在评论平均长度只有几十字的场景下这种做法勉强能跑，但有三类问题反复出现。第一，一条评论里常常同时谈到「早餐很差、隔音不错、前台很好」等多个主题，把整条评论压成一个向量与一份倒排文档之后，单一主题就会被其它内容稀释，用户问「早餐怎么样」时，本该最相关的评论排名反而下降。第二，模型每次只能整段引用一条评论，前端也只能整条高亮，用户拿到的是一整段长文，还要自己再去文里找证据句，体验上离「精确定位被引用的内容」相去甚远。第三，长评论里的非主题部分容易把检索带偏，比如用户问网络，而某条评论几乎全在讲早餐、只在结尾提了一句 Wi-Fi，这种评论也会被错误地排到前面。

\subsection{方案}

整体思路是把「一条评论 = 一份文档」改成「一条评论包含若干句子级的 chunk」，让检索在更细的粒度上进行，同时让前端能直接知道哪一句被命中、把那一句标亮。具体的切分策略在「按句子切」「按固定长度滑窗切」「按主题相似度切」三种方案之间做了权衡。第三种效果上限最高但要先训练或调用一个主题分类器，工作量与依赖都比较重，最终选择的是「以句子切分为主，遇到特别长的句子再叠一层滑窗」，过短的句子与相邻句合并以避免噪声，整套切分逻辑大约 60 行，便于后续替换或对照实验。

检索过程也相应做了调整。让 BM25 先在更细的句子级 chunk 上做召回，结果整理完之后再按「来自同一条评论」做归并，每条评论只保留得分最高的那一句作为「代表句」，并把这句话在原评论中对应的字符位置一起返回。这样得到的结果对外仍然是「一条条评论」的形式，老的接口和前端组件都不用动，但每条评论上多挂了一个「这条评论是因为这一句被命中」的元信息。前端拿到这条信息后，把原评论里对应的那一段文字直接套上 \texttt{<mark>} 高亮即可，整个过程不依赖模型自己输出位置，因而既稳定又零额外成本。如果分块索引由于某种原因不可用，系统也会自动回退到原来的整条评论检索，不会因为优化引入风险。

\subsection{效果}

切分之后整库由 2171 条评论展开为 7883 个句子级 chunk，每条评论平均 3.63 个 chunk，平均文档长度由 41 词左右降到 12 词左右，但整库的词表规模几乎没变，说明这次改造改变的是「文档怎么切」而非「引入新的内容」。多样性方面也有明显变化，在 100 个 Query 的离线对比中，Top-30 命中里覆盖了将近 29 条不同评论，且每条评论平均只被一个代表句命中，避免了同一条长评论靠多个 chunk 反复挤占榜单的情况。表~\ref{tab:chunk} 给出了这些指标的前后对比，可以看到分块在保持词表稳定的前提下，让召回的粒度与覆盖面同步向更细的层级靠拢。

\section{Prompt 结构化优化}

\subsection{痛点}

原本的 Prompt 把所有信息都堆在一段长文本里，包括系统角色、历史对话、当前问题、检索回来的评论与摘要、以及十几条要求和引用规则。这样写出来的 Prompt 看着信息齐全，但模型并不容易抓住重点，几类问题会反复出现。一是回答经常先来一大段铺垫式的总结，再罗列优点缺点，对用户真正问的那个点反而轻描淡写。二是引用记号经常不合规，比如把四五条引用塞在同一个记号里、或者把同一个引用拆成两个挨在一起的小记号，前端解析与高亮就容易出问题。三是同一类问题在不同次回答里段落结构反复变动，前端很难做稳定的样式与跳转。这些问题的根源在于约束被平铺在一起，模型缺少一个明确可依的回答骨架。

\subsection{方案}

整体思路是借鉴常见的结构化 Prompt 写法，把原来的一团信息拆成五个清晰分工的小段：第一段交代「你是谁、能做什么、不能做什么」，约束模型只能基于检索回来的评论与摘要回答；第二段提供「上下文」，包括今天的日期、当前问题、检索回来的评论与摘要，并按需注入历史对话，仅在用户出现「那、还有、它、是吗」这类追问性质的表达时，才把上一轮带进来，避免无关历史污染当前回答；第三段告诉模型「你这次要做什么、回答应该长成什么样」，给出一个固定的输出骨架；第四段把反幻觉、客观性、简洁性、闲聊边界、Markdown 等约束精炼成五条编号要求，让模型逐条对照；第五段是「自我校验」，要求模型在内心回看一遍引用是否合规、再把不合规的写法自己改正过来，但不把这个过程写进最终回答。这样改下来的好处是结构清楚、责任分明，模型每段都知道该做什么，输出也更接近一个稳定的模板，而不是每次自由发挥。

\subsection{效果}

经过五段式重构之后，模型在面对「近期入住花园大床房的住客体验如何」这类典型问题时，能稳定输出「先一句结论 + 几个带引用的要点 + 一句风险提示」的三层结构，引用全部以合规的蓝色徽标渲染，几乎没再出现把多条引用拆开或塞在一起的情况。图~\ref{fig:answer} 是真实链路上的一次回答展示，开头一句先总括「房间舒适度普遍获得高度评价、卫生状况则呈现明显分化」，随后用三条带引用的要点分别覆盖房间布局与设施、文化氛围与空间体验、以及卫生方面的隐含风险，最后以一句关于敏感人群体验的风险提示收束，每条要点的引用都直接挂回到下方的评论卡片，用户可以点开继续验证证据。整体阅读体验比改造前的「长篇铺陈」明显更聚焦，前端也能依赖这个稳定结构做二级渲染与样式收敛。

\section{多样性重排（MMR 与 DPP）}

\subsection{痛点}

现有排序模块在融合相关性、内容质量与时效性三个维度的特征后，直接按综合得分从高到低取 Top-10 返回。这种纯贪心策略在酒店评论场景下存在明显的信息冗余问题：当用户问「早餐怎么样」时，排名靠前的评论可能全部集中在自助早餐的品种丰富度上，而中餐厅早餐、行政酒廊早餐、room service 早餐等其他角度的信息被完全忽略。返回的 10 条评论虽然在单条层面上都「相关」，但在集合层面上高度同质——它们反复在说同一件事的不同措辞版本，对用户的决策参考价值有限。根本原因在于贪心排序只关注每条评论自身的质量，完全不考虑所选集合内部的信息重叠程度。

\subsection{方案}

在原有排序流程中插入一个可选的多样性重排阶段。具体来说，在 \texttt{MultiFactorRanker} 完成 100 条候选评论的多因子打分之后、截取 Top-10 之前，调用多样性重排器从 100 条中选出 10 条兼顾相关性与集合内差异度的评论。整个阶段通过参数 \texttt{diversity\_method} 控制，支持三种算法，实现为独立的 \texttt{DiversityReranker} 模块（\texttt{diversity.py}）。

\textbf{MMR（Maximal Marginal Relevance）。}经典的最大边际相关性算法，每轮贪心选取使 \(\lambda\cdot\text{score}(d_i)-(1-\lambda)\cdot\max_{d_j\in S}\text{sim}(d_i,d_j)\) 最大化的候选。其中 \(\text{score}(d_i)\) 复用现有多因子综合得分（已归一化），\(\text{sim}(d_i,d_j)\) 为评论 text-embedding-v4 向量的余弦相似度，\(\lambda\in[0,1]\) 控制相关性与多样性的权衡。

\textbf{DPP（Determinantal Point Process）。}构造核矩阵 \(L_{ij}=q_i\cdot S_{ij}\cdot q_j\)，其中质量项 \(q_i=\text{score}_i^{\theta}\)（\(\theta>1\) 放大高分差距、偏向相关性，\(\theta<1\) 压缩差距、偏向多样性），相似度项 \(S_{ij}=(\cos\_\text{sim}_{ij}+1)/2\) 映射到 \([0,1]\)。采用贪心 MAP 推断，每轮选取使 Schur 补增益 \(\text{gain}(i)=L_{ii}-\mathbf{L}_{iS}\mathbf{L}_{SS}^{-1}\mathbf{L}_{Si}\) 最大的候选。

\textbf{Fast-DPP。}先用 k-means（\(k=2\times\text{topk}\)）将候选按 embedding 聚类，每簇内仅保留得分最高的 3 条进入 DPP 精排，将复杂度从 \(O(N^2K)\) 降至 \(O(N\cdot c+M^2K)\)。

为量化评估效果，排序模块对所有请求（包括 baseline）均计算 Top-10 结果的 mean pairwise cosine similarity 并写入响应元数据，该值越低说明返回集合的冗余越少。

\subsection{效果}

在 30 个评估问题上对 1 组基线 + 3 组 MMR（\(\lambda=0.3,0.5,0.7\)）+ 3 组 DPP（\(\theta=0.5,1.0,2.0\)）共 7 种配置进行消融对比。综合得分定义为 \(\text{composite}=0.4\times\text{avg\_relevance}+0.6\times(1-\text{mean\_pairwise\_sim})\)，其中第二项直接衡量返回集合的去冗余程度。

结果如表~\ref{tab:diversity} 所示。\textbf{三组 MMR 配置全部优于 baseline}，验证了多样性重排的有效性。MMR \(\lambda=0.3\) 以最高的多样性质量（\(1-\text{sim}=0.461\)）取得最优综合得分 0.490，相比 baseline（0.458）提升 7.0\%。从 \(\lambda=0.7\) 到 \(\lambda=0.3\)，成对相似度从 0.603 单调降至 0.539，类别覆盖率逐步上升，同时相关性从 0.591 降至 0.534，呈现清晰的多样性-相关性权衡曲线，完全符合 MMR 理论预期。图~\ref{fig:tradeoff} 直观展示了这一权衡关系。

DPP 三组在降低相似度方面表现符合预期（sim 均低于 baseline），但相关性损失过大（rel 仅 0.40 左右，比 baseline 低约 33\%），导致综合得分反而不及 baseline。根因在于 DPP 核矩阵中质量项与相似度项的耦合方式在当前分数分布下过度放大了多样性维度，后续可通过引入质量-多样性混合系数或调整核矩阵构造方式改进。

\section{多轮对话上下文管理}

\subsection{痛点}

原系统的「多轮对话」支持仅限于将上一轮的 \texttt{\{user, assistant\}} 作为 \texttt{history} 字段传回后端，由 Prompt 模板中的硬编码触发词列表决定是否注入。这套机制存在五个结构性问题。第一，仅存上一轮，超过两轮的对话信息全部丢失。第二，追问判断依赖固定触发词（「那、还有、这个……」），像「隔音怎么样？」这种省略主语的完整中文追问无法被识别。第三，检索阶段完全无上下文感知，追问「那午餐呢？」时仍用原始 query 检索，不会自动补全为完整问题。第四，无 token 预算管理，多轮累积可能超出模型上下文窗口。第五，prompt 模板与生成器未对多轮场景做结构化适配，对话历史仅作为一段平文拼接，缺少分层组织。

\subsection{方案}

新增 \texttt{ConversationManager} 作为 RAG 系统的有状态会话层（\texttt{conversation.py}），在 FastAPI 应用级别维护 \texttt{session\_id → ConversationManager} 的映射字典，前端通过 UUID 标识会话并持久化于 sessionStorage。整个多轮对话管线分为三个阶段。

\textbf{查询消解。}在意图识别之前，新增 \texttt{QueryResolver} 模块。当会话已有历史轮次时，将当前 query 与最近几轮对话一并送入 qwen-flash 做指代消解与主语补全：例如「隔音怎么样？」结合上文「红棉套房的床品舒服吗？」被消解为「红棉套房的隔音怎么样？」。消解后的完整 query 替代原始 query 进入意图识别→意图扩展→混合检索流程，确保检索阶段也受益于对话上下文。同时，\texttt{IntentExpander} 在意图扩展时接收对话上下文，使子意图的生成更贴合多轮语境。

\textbf{分层上下文注入。}生成阶段的 Prompt 新增 v2 模板（\texttt{prompts.py}），对话历史按三层优先级组织：Layer~1 为最近 2 轮完整问答（追问时最关键），Layer~2 为中间轮次的话题摘要，Layer~3 为 LLM 压缩的长期摘要。三层按 token 预算（默认 1200 tokens）自顶向下逐层注入，超出预算的低优先层级自动截断。v2 模板增加了「多轮连贯性」约束，要求模型在回复开头使用衔接词（如「确实」「此外」「关于您提到的」）自然呼应上文。

\textbf{对话摘要压缩。}当轮次超过阈值（默认 4 轮）时触发 \texttt{ContextCompressor} 将最早 2 轮对话压缩为 1--2 句摘要，追加到长期摘要缓冲区，同时释放旧轮次占用的 token 空间。整套机制为每个会话维护完整的轮次列表（最多保留 10 轮）与渐进式摘要，支持序列化以对接前端 sessionStorage，会话 30 分钟无活动自动过期。

\subsection{效果}

图~\ref{fig:multi1} 与图~\ref{fig:multi2} 分别展示了同一会话中连续两轮的真实问答交互。首轮用户提问「早餐怎么样？」，系统正常返回检索评论与流式回答。第二轮用户输入追问「那午餐呢？」，服务端 \texttt{QueryResolver} 自动将其消解为完整问题，随后以消解后的 query 完成检索与生成。整个过程对用户透明，前端无需修改 UI 逻辑即可获得多轮连贯体验。在 5 组手工构造的多轮场景（含指代消解、主语省略、跨轮对比、话题切换、长对话压缩）的测试中，查询消解与上下文注入在各场景下均正确生效。
